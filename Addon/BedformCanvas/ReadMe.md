# Bedform Canvas

Private workspace `bedform-canvas` 1.0.0 provides the independently buildable behavior
and resource pack scaffold for shared Bedform terminal/spatial display resources.
Both manifests use format 2 and engine minimum 1.26.60. The behavior pack depends on
the resource pack at the same version and `@minecraft/server` 2.10.0. Its data and
JavaScript modules have separate, stable UUIDs.

```sh
npm run build --workspace bedform-canvas
npm run check --workspace bedform-canvas
```

The builder writes `Addon/BedformCanvas/dist/bedform-canvas.mcaddon`. It contains
`bedform-canvas-bp.mcpack` and `bedform-canvas-rp.mcpack`, each with `manifest.json`
at its root, `License.txt` and `AssetProvenance.md`. The behavior pack additionally
contains `scripts/main.js`, compiled from `Script/Main.ts` with esbuild. All other
files beneath the authored pack directories are included recursively, including
future assets and upstream notices. Symlinks and generated-file collisions fail
the build. Builds require the repository's Node dependencies, with no Bedform CLI,
Minecraft client, network, native server or world access.

File ordering, compression, ZIP timestamps and permissions are fixed. The builder
validates package/manifest version agreement, distinct UUIDs, script configuration
and dependencies before publication. It builds in memory and replaces the final
archive with a rename from a temporary sibling directory. Failed input validation
or compilation preserves the previous archive. Source pack directories are never
rewritten. `Build(outputDirectory?, sourceDirectory?)` also supports independent
workspace snapshots. Tests compare isolated builds, changed file mtimes and
different process timezones, inspect both inner archives and check failure safety.
`check` runs scoped lint, script/tool/test types, the glyph freshness check, tests and a
final build.

`Script/Main.ts` starts session-only Intent arbitration (`Script/IntentRuntime.ts`)
and the private Intent renderer (`Script/IntentRenderer.ts`). It subscribes to script
events, entity death and player leave, schedules one timer per timed request and
refreshes presentation every tick. It writes no world state and starts no display
restoration or VM. The renderer reads the arbitration service's `Snapshot` handle.
Ambiguous `entityRemove`
notifications (which include chunk unloads) never clear a request: the subject is
suspended and resumes on reload. See the
[runtime lifecycle](../../Package/Bedform/Documentation/intent.md#canvas-runtime-lifecycle).
Canonical display/VM entities and persistence belong to `MineCraft-9rdk.10`.
Frame generation belongs to `MineCraft-9rdk.9`.

The custom glyph catalogue (`MineCraft-ty2k.9`) is generated by `Tool/Glyph/` from
checked-in inputs: dark gray TextPrimitive font pages E2 to EB, matching white particle
textures and particle definitions, upstream notices and the typed catalogue read through
`Public/Glyph.ts` (lookups, the switch cell and the RGB/RGBA tint contract). Run
`npm run glyph` to regenerate and `npm run glyph:capture` to refresh inputs from the
installed client. The [asset inventory](Assets/ReadMe.md) records allocation, provenance,
licensing and the font/particle tint contract. Demo sources and assets are unchanged;
unrelated DDUI/control content and all Common identities stay in Common.

The client contract now lives at `bedform/Canvas/IntentProtocol` and is forwarded
by `Public/Intent.ts`; the shared runtime must import those keys and types instead
of repeating script-event identifiers. See the
[Intent client and wire contract](../../Package/Bedform/Documentation/intent.md).
A ready hello means this runtime's complete request handler is installed.

Bedform's normal/pure/prepack preparation bundles this archive in its npm package.
[Feature-based staging](../../Package/Bedform/Documentation/canvas-packs.md) includes
it once for surviving asset-backed runtime use or explicit Canvas dependencies.
Shared [custom-image compilation](../../Package/Bedform/Documentation/canvas-images.md)
now supplies virtual descriptors and staged consumer textures/particles through `.6`.
Host checks establish the archive contract, deterministic arbitration and renderer
adapter calls. `npm run test:native --workspace bedform-canvas` qualifies native
delivery and the lifecycle on an isolated BDS at the fixed `dist/bds-runtime` path,
with two independent consumer packs; see the
[native qualification](Documentation/Native.md). Real-client acceptance remains separate.
Run `npm run verify:intent --workspace bedform` for the combined
[automated qualification matrix](../../Package/Bedform/Documentation/intent-qualification.md),
retained gate logs and artifact hashes across normal, pure and prepack preparation.

## Intent artwork and presentation

`Tool/IntentArt.mts` generates all nineteen built-in icon textures, camera-facing and
oriented particle definitions and `Public/IntentArt.generated.ts` descriptors. Ordinary
generation reads checked-in source pixels; only `intent:art:capture` reads a client.
The existing Canvas Ten glyph source supplies SOS; it allocates no new font cells.
The renderer composes the scalable gray panel, bevel, lower shadow and pointer from
the shared rectangle particle. Its default body is 32 by 24 logical pixels, with a
four-pixel pointer, at 32 pixels per block. Measured PUA glyphs expand its dimensions.

```sh
npm run intent:art --workspace bedform-canvas
npm run intent:art:check --workspace bedform-canvas
npm run intent:art:capture --workspace bedform-canvas
```

Generation writes an icon/frame contact sheet to `dist/intent-preview.png`. Source
provenance and licensing are in [Assets/ReadMe.md](Assets/ReadMe.md). `check` verifies
artwork freshness, all descriptor/texture/particle references, source shape and alpha,
arrows' lower-right shadows, animation timing and archive reproducibility. The
[Intent rendering contract](../../Package/Bedform/Documentation/intent.md#private-rendering)
documents audiences, metrics, layers, budgets and failure cleanup. Server-side audiences
are qualified natively by `.9`; two-client appearance, occlusion and text calibration
remain `.10` acceptance work.
